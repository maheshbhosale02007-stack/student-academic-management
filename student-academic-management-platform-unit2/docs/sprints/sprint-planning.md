# Sprint Planning Document

## Sprint Length

Recommended: **2 weeks per sprint**.

## Sprint 1 — Authentication and Project Setup

### Goal
Establish the secure application foundation.

### Sprint Backlog
- Repository initialization
- Basic application structure
- US-16 User Login
- US-17 Logout
- US-19 Role-Based Access
- Basic UI
- Authentication testing

### Expected Increment
A user can authenticate and access role-appropriate areas of the application.

## Sprint 2 — Student Management

### Goal
Deliver the core student record workflow.

### Sprint Backlog
- US-01 Add Student
- US-02 Search Student
- US-03 Update Student
- US-04 Delete/Deactivate Student
- Student management UI
- Student module testing

### Expected Increment
Authorized staff can create, find, update, and manage student records.

## Sprint 3 — Course and Attendance

### Goal
Deliver course enrollment and attendance management.

### Sprint Backlog
- US-05 Add Course
- US-06 Update Course
- US-07 Assign Students
- US-08 View Course
- US-09 Record Attendance
- US-10 View Attendance
- US-11 Attendance Report

### Expected Increment
Courses can be managed, students can be assigned, and attendance can be recorded and reviewed.

## Sprint 4 — Marks and Academic Performance

### Goal
Deliver academic performance workflows.

### Sprint Backlog
- US-12 Enter Marks
- US-13 Update Marks
- US-14 Calculate Grades
- US-15 Result Sheet

### Expected Increment
Authorized staff can record marks and generate verified academic results.

## Sprint 5 — Notifications and Reporting

### Goal
Improve communication and academic reporting.

### Sprint Backlog
- US-20 Attendance Alert
- US-21 Examination Notification
- US-22 Result Notification
- US-23 Student Report
- US-24 Attendance Report
- US-25 Performance Report
- US-26 Course Report

### Expected Increment
Users receive important notifications and authorized staff can generate academic reports.
