# IBM Loop Documentation — Observe → Reflect → Make

## Observe

### Evidence to Collect
- Student interviews
- Faculty workflow observation
- Administrative process mapping
- Examination workflow review
- IT/security constraints

### Initial Observations
- Academic information is used by multiple stakeholder groups.
- Different roles need different levels of access.
- Attendance and reporting involve repetitive operations.
- Accuracy and security are essential.

## Reflect

### Insights
1. A single centralized record can reduce duplication.
2. Role-specific dashboards can reduce unnecessary complexity.
3. Validation should happen close to data entry.
4. Reporting should use trusted centralized data.
5. User feedback must influence subsequent iterations.

## Make

### Initial Product Decisions
- Use role-based dashboards.
- Centralize student and course data.
- Add validation to important forms.
- Provide attendance and reporting workflows.
- Maintain an audit trail.

## Next Loop

After prototyping, observe task completion, reflect on usability issues, and make the next prototype iteration.
