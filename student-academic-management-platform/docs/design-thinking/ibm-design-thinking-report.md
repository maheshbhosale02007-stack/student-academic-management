# IBM Design Thinking Report

## Principles

### 1. Focus on User Outcomes

The project measures success through outcomes rather than only features. Students should be able to access accurate academic information, while staff should complete academic workflows with less effort and fewer errors.

### 2. Restless Reinvention

The solution should continuously improve through research, prototype testing, feedback, and iteration rather than assuming the first design is final.

### 3. Diverse, Empowered Teams

Students, faculty, administrators, examination staff, and IT representatives should contribute different perspectives. The team should be empowered to make evidence-based design decisions.

## Hills / Key User Outcomes

- Easy access to academic information
- Faster attendance management
- Reliable academic records
- Faster report generation
- Secure access

## Playbacks

The team should regularly review findings with stakeholders to confirm that requirements and proposed workflows reflect actual needs.

## Sponsor User

A representative academic administrator can act as a sponsor user who provides domain feedback and validates major product decisions.

## Iterative Approach

Observe users → reflect on evidence → make improvements → test again.
