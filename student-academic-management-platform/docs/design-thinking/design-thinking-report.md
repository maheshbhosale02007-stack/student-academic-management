# Design Thinking Report

## 1. Empathize

The team considers the experiences of students, faculty, administrators, examination staff, and IT support.

### Key observations

- Students want quick access to academic information.
- Faculty need efficient attendance workflows.
- Administrators need reliable centralized records.
- Examination staff need accurate result processing.
- IT staff need security, maintainability, and operational visibility.

## 2. Define

### Problem Statement

Higher-education stakeholders need a centralized and secure academic record platform because fragmented and manual processes make student information difficult to maintain, access, verify, and report accurately.

### How Might We

**How might we make academic record management faster, safer, and easier for students and staff?**

## 3. Ideate

Potential ideas:

1. Centralized student profile.
2. Role-based dashboards.
3. Digital attendance register.
4. Automated attendance calculation.
5. Result validation workflow.
6. Academic report generator.
7. Search and filtering.
8. Audit trail for important changes.
9. Notification center for academic updates.

## 4. Prototype

The proposed low-fidelity prototype contains:

- Login screen
- Student dashboard
- Faculty dashboard
- Administrator dashboard
- Student record form
- Attendance screen
- Results screen
- Report generation screen

## 5. Test

Prototype testing should involve representative users completing realistic tasks.

### Example tasks

- Student: Find current attendance.
- Faculty: Mark attendance for a class.
- Administrator: Create a student record.
- Examination staff: Verify and publish results.

### Feedback Questions

- Was the task easy to understand?
- Were labels clear?
- Could the user find the required action?
- What caused confusion?
- What should be improved?

## Expected Iteration

Test results should be converted into improvements and retested. The design is not considered final until core user tasks are understandable and efficient.
